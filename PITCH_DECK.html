VERDICT

The alert is a hypothesis. Not a verdict.

An autonomous SOC agent that proves whether an attack actually succeeded — then takes the narrowest safe response.

Team VerdictIIT Bhubaneswar
The Problem

Most "AI SOC agents" are classifiers wearing a badge.

A NIDS alert names a CVE and a severity. That's a claim, not a fact — most attempts against most targets fail: wrong version, already patched, port closed. A system that reads the label and blocks is pattern-matching. It isn't investigating.

nids_alerts · severity: low

ET EXPLOIT ProxyLogon SSRF · CVE-2021-26855

A label-only reading calls this benign because severity reads "low". The target is running an unpatched Exchange build — and it's compromised.

35% accuracy of an alert-label-only baseline on our 40-incident set

VERDICT03 · Approach
Architecture

One loop. Nine steps. State persists across all of them.

A single orchestrator plus one Evidence Auditor verifier — that's the whole architecture. The brief scores zero points for agent count; we didn't build a six-agent mesh to look busy.

ledger evidence_store action_log case_status — persisted per case.

1  INGEST — alert → structured claim
2  PLAN — highest information-gain tool
3  ACT — call one read tool
4  OBSERVE — update the ledger, cite the artifact
5  STOP-CHECK — confident, or budget spent
6  DECIDE — tier + blast-radius gate
7  EXECUTE — narrowest sufficient action
8  VERIFY — re-probe, never trust a 200 OK
9  WATCH — new evidence can reopen the case
VERDICT04 · Architecture
Mechanism · Response

The narrowest rule that works. Escalate before anything wider.

Before any firewall action, VERDICT walks the CMDB for peer dependencies and live sessions. A single-target attack gets a scoped block; only a multi-target spray forces a wider rule — and a wider rule only executes autonomously if it costs nothing real.

narrow · executes autonomously

block 203.0.113.191 → 10.2.2.16:443

Single target. Collateral: 0 legitimate sessions, 0 users.

broad · escalates to a human

block 203.0.113.191 → * (all ports/dst)

Attacker spraying 2 targets through a shared NAT. Collateral: 4 legitimate sessions, 340 users.

VERDICT05 · Blast Radius
Mechanism · Trust

Every claim in the report cites a real artifact. Or it doesn't survive.

A second pass parses the incident report and checks each evidentiary claim against the case's actual evidence store. Uncited claims are stripped and flagged before a human ever reads them.

VERDICT06 · Evidence Auditor
Adaptation · Live, On Demand

Three ways we break it. On camera. Every time.

01 · evidence reversal

Closed FAILED. Late beacon evidence arrives.

Case reopens, re-derives from scratch, verdict flips to SUCCEEDED — unprompted.

02 · silent firewall failure

fw_apply returns 200 OK. Twice. Traffic still flows.

The agent never trusts the response — it re-probes, catches the lie, falls back to EDR quarantine.

03 · override → auto-rollback

Agent escalates. Human overrides. Agent complies —

then re-probes, finds a legitimate session dropped, and rolls itself back to the narrow rule, reporting exactly why.

An agent that obeys a human, catches the human's mistake, and safely undoes it.

VERDICT08 · Results
Challenges

What was actually hard to get right.

A solvable-but-not-trivial environment

40 incidents where the ground truth is genuinely derivable, not guessable — verified with a hand-playbook acceptance test before trusting any agent number.

Autonomy without hallucination

The LLM planner chooses what to inspect next; every tool argument is still resolved deterministically from real evidence, so it can never invent an IP or a version.

Blast radius has to emerge from behavior

The override scenario only escalates because the attacker is genuinely spraying two targets — the collateral number comes from real session data, never hand-tuned.

Verification that actually verifies

A 200 OK from the firewall proves nothing. Only re-probing the live ruleset does — that distinction is the entire silent-failure mechanism.

VERDICT09 · Challenges
Conclusion

An agent that investigates before it acts, and undoes its own mistakes.

VERDICT doesn't classify alerts — it adjudicates them, computes the cost of being wrong before acting, and audits its own evidence. That's the difference between automation and judgment.

The alert is a hypothesis. Not a verdict.
